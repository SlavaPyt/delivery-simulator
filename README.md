# Консольный симулятор службы доставки

Практическая работа №1 по дисциплине «Объектно-ориентированное программирование»
(кафедра САПР, СПбГЭТУ «ЛЭТИ»).

Консольное приложение на Java моделирует работу небольшой службы доставки: можно создать заказ
с несколькими позициями, выбрать способ доставки и увидеть рассчитанные стоимость и срок, назначить
курьера и провести заказ по допустимым статусам. Программа работает только в памяти: файлы, база
данных, сеть и графический интерфейс не используются.

## Возможности

| Пункт меню | Что делает |
|---|---|
| Создать новый заказ | Запрашивает клиента, адрес и одну или несколько позиций |
| Добавить позицию в заказ | Добавляет позицию в заказ со статусом «Новый» |
| Показать список заказов | Таблица: номер, клиент, статус, доставка, курьер, сумма |
| Показать информацию о заказе | Подробные данные одного заказа |
| Выбрать способ доставки | Показывает стоимость и срок каждого способа и применяет выбранный |
| Назначить курьера | Выбор из свободных курьеров (если способ доставки требует курьера) |
| Изменить статус заказа | Показывает только допустимые переходы и новую информацию о заказе |
| Показать курьеров / Добавить курьера / Изменить статус курьера | Управление курьерами |
| Выход | Завершает работу по явной команде `0` |

На любом вопросе можно ввести `отмена` (или `cancel`), чтобы прервать текущую операцию.
Некорректный ввод не завершает программу: выводится понятное сообщение и значение запрашивается
заново.

### Способы доставки

| Способ | Стоимость | Срок | Курьер |
|---|---|---|---|
| Стандартная доставка курьером | 250 руб., бесплатно от 3000 руб. | до 2 суток | нужен |
| Экспресс-доставка | 500 руб. + 5 % от стоимости товаров | до 2 часов | нужен |
| Самовывоз | бесплатно | до 1 часа | не нужен |

### Статусы заказа

```
Новый ──► Подтверждён ──► В доставке ────────► Выполнен      (курьерские способы)
   │            │     └─► Готов к выдаче ───► Выполнен      (самовывоз)
   └────────────┴──────► Отменён  (из любого нефинального статуса)
```

Подтвердить заказ можно только при наличии позиций и выбранного способа доставки. Передать заказ
в доставку можно только после назначения курьера. При завершении или отмене заказа курьер
освобождается.

## Сборка и запуск

Нужен JDK 17 или новее. Gradle устанавливать не нужно — используется Gradle Wrapper.

```bash
./gradlew run --console=plain     # запуск программы
./gradlew test                    # модульные и сквозные тесты
./gradlew build                   # полная сборка: компиляция, проверка стиля, тесты
./gradlew installDist             # запускаемый дистрибутив в build/install/
```

В Windows используйте `gradlew.bat` вместо `./gradlew`; чтобы кириллица в консоли отображалась
верно, выполните перед запуском `chcp 65001`.

Если ввод идёт из файла или канала (`./gradlew -q run --console=plain < сценарий.txt`), введённые
строки повторяются в выводе, и запись сеанса получается читаемой.

## Структура проекта

```
src/main/java/ru/leti/delivery
├── Main.java                  точка входа, сборка компонентов
├── model                      предметная область
│   ├── Person, Customer, Courier
│   ├── Order, OrderItem, OrderStatus
│   ├── DeliveryMethod         общий контракт способа доставки
│   ├── Validation             проверки входных данных
│   └── delivery               StandardDelivery, ExpressDelivery, PickupDelivery
├── service                    OrderService, CourierService, DeliveryQuote
├── console                    ConsoleApp (меню), ConsoleInput, ConsolePrinter
└── exception                  DeliveryException и его наследники
```

Как реализованы требования к ООП-структуре:

- **Разделение ответственности.** `ConsoleInput` только читает ввод, `ConsolePrinter` только
  печатает, `ConsoleApp` ведёт диалог, `OrderService` и `CourierService` управляют данными, а
  правила предметной области проверяет модель. `main` лишь собирает объекты.
- **Инкапсуляция.** Поля закрыты; статус, позиции и курьер меняются через методы `Order`
  (`addItem`, `chooseDeliveryMethod`, `assignCourier`, `changeStatus`), которые проверяют
  допустимость операции и выбрасывают понятные исключения.
- **Композиция.** `Order` содержит `Customer`, список `OrderItem` и выбранный `DeliveryMethod`.
- **Полиморфизм.** Каждый способ доставки сам считает стоимость и срок, сообщает, нужен ли курьер,
  и определяет статус после подтверждения. Код оформления заказа не содержит цепочек проверок
  типа доставки; новый способ добавляется классом и одной строкой в `Main`.
- **Наследование.** `Customer` и `Courier` наследуют общие поля `Person`; курьерские способы
  доставки — `CourierDelivery`.

## Стиль кода и тесты

Код оформлен по [Google Java Style](https://google.github.io/styleguide/javaguide.html).
Форматирование проверяет Spotless (`google-java-format`) в составе `./gradlew build`; исправить
замечания автоматически можно командой `./gradlew spotlessApply`.

Тесты (JUnit 5) покрывают модель, способы доставки, сервисы, ввод и вывод, а также сквозные
сценарии работы с меню.
